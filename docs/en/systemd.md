| Unit | Generated path | Command it runs | User |
| --- | --- | --- | --- |
| `yaagwadb.service` | `/etc/systemd/system/yaagwadb.service` | The daemon (`yaagwadb daemon`) | `yaagwadb` |
| `yaagwadb-mount.service` | `/etc/systemd/system/yaagwadb-mount.service` | The mount (`yaagwadb mount`). Depends on `yaagwadb.service` | root |
| `yaagwadb-hrana.service` | `/etc/systemd/system/yaagwadb-hrana.service` | hrana (`yaagwadb hrana`). Depends on `yaagwadb.service` | `yaagwadb` |

See [config.md](config.md) for the configuration items.

## Prerequisites

The units hold the following values as fixed. `yaagwadb install` does not create them.

- The binary path is `/usr/local/bin/yaagwadb`
- The configuration file path is `/etc/yaagwadb/config.toml`. Even if `install -c` writes the configuration file elsewhere, the units read this path. To use another location, edit `ExecStart` in the units
- The daemon and hrana run as the `yaagwadb` user and group. Create the user beforehand
- The configuration file is written owned by root with mode `0640`. Change its group so that the `yaagwadb` group can read it

## Installation

```sh
sudo install -m 0755 yaagwadb /usr/local/bin/yaagwadb
sudo useradd --system --no-create-home --shell /usr/sbin/nologin yaagwadb
sudo yaagwadb install
sudo chown root:yaagwadb /etc/yaagwadb/config.toml
sudo systemctl daemon-reload
sudo systemctl enable --now yaagwadb.service
sudo systemctl enable --now yaagwadb-mount.service   # if you use the mount
sudo systemctl enable --now yaagwadb-hrana.service   # if you use hrana
```

Another path can be specified with `yaagwadb install --unit-directory`

- `yaagwadb install` leaves an existing configuration file and existing units unchanged. It prints `wrote` for each file it writes and `kept existing` for each file it leaves
- To replace the units with those of a newer version, delete the existing units and run `yaagwadb install`

## Writable directories

The daemon and hrana units set `ProtectSystem=strict`. Only the following directories, prepared by systemd, are writable.

- `/var/lib/yaagwadb` (`StateDirectory`, mode `0700`)
- `/run/yaagwadb` (`RuntimeDirectory`, mode `0755`)

If `data_directory` or `socket` in the configuration file points elsewhere, add `ReadWritePaths=` to the unit.

## Startup

- When the mount or hrana starts, the daemon must already be running and able to respond
- The units use `Type=simple`, so systemd may start the mount or hrana before the daemon listens on the socket. The mount or hrana then exits with `yaagwadb: cannot connect to the daemon`, and `Restart=on-failure` restarts it after 2 seconds
- The mount runs as root, so it can connect to the `0600` socket (see "Connecting" in [grpc.md](grpc.md))
